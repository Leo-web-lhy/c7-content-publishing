我用 AI 把一门斯坦福课程翻成中文，全程 7 分 47 秒

标题候选（A/B 测试用）：
1. 我用 AI 把一门斯坦福课程翻成中文，全程 7 分 47 秒
2. 21038 字、342 行，7 分 47 秒：一次真实的 AI 课程翻译
3. 别再用 AI 一键翻译了，这样用才不出错

一、先说结论

一门斯坦福的 Vibe Coding 课程，21038 个字符、342 行，从抓取到翻译到校验到发布，全流程 7 分 47 秒。

但这个数字不是重点。重点是：如果我只把「翻译」交给 AI，这事一定做砸。 真正花时间的不是翻译，是「怎么知道它翻对了」。

下面是我完整的做法，包括三个我踩过的坑。

二、为什么不能「一键翻译」

第一次我偷懒，直接把整份英文原文丢给 AI，说「翻译成中文」。

结果有三个问题：

  1. 术语前后不一致：同一个 prompt，第一段叫「提示词」，第五段叫「提示」，第十段叫「指令」。
  2. 格式塌了：原文里的标题层级、代码块、表格，翻译后变成一团。
  3. 没法核对：AI 翻完你只能整篇读一遍，读到第三千字就困了，剩下的靠「感觉没问题」。

一键翻译的本质问题是：它给你一个结果，却不给你任何可验证的中间状态。

所以我改成四阶段流水线，每个阶段都留证据。

三、四阶段流水线（附真实耗时）

阶段做什么真实耗时
① 抓取归仓定位一手来源，批量抓取，落盘存档12:26:46–12:27:25（约 39 秒）
② 术语表先行先让 AI 抽取术语，人工确认后冻结12:27:25–12:29:12（约 1 分 47 秒）
③ 分段翻译按段落切块，逐块翻译，带上术语表12:30:01–12:31:55（约 1 分 54 秒）
④ 质量抽检逐段核对字符数、术语一致性、格式完整性12:33:56–12:34:33（约 37 秒）

合计约 7 分 47 秒。

注意阶段 ② 的顺序：术语表必须在翻译之前冻结。

这是整个流程里最关键的一个决定。AI 是记不住「全局一致性」的——它每一段都是独立生成的，你不告诉它「prompt 永远叫提示词」，它就会自由发挥。

先冻结术语表，再翻译，一致性就从「靠运气」变成「靠约束」。

四、三个真实的坑

坑 1：21038 和 21209 都不是错的

我第一次报字数，写的是 21209。后来发现：

  • 21209 是字节数
  • 21038 是字符数（真正该报的）

中文一个字在 UTF-8 里占 3 个字节。混着报，看起来差得不多，但性质完全不同：一个说「文件多大」，一个说「内容多长」。

教训：报数字的时候，必须连单位一起报，并且自己先算一遍。

后来我把 README、日志、说明文档里所有出现的地方统一改成 21038 字符 / 342 行。四处修改，逐处核对。

坑 2：脚本跑通了，但什么都没输出

我在 Windows 上跑一个 Python 脚本，退出码是 0，看起来很成功——但一个文件都没写出来。

查了很久才发现：这是本机「中文路径 + 非 ASCII 控制台输出」的崩溃模式，进程直接以 0xC0000005（3221225477）死掉，而且死之前不落任何日志。

解决办法不是「修好它」，而是绕开它：

  • 脚本源码保持纯 ASCII，中文只放在数据 JSON 里
  • 控制台只打印 ASCII 统计行（例如 RC=0 lines=342）
  • 明细写进 UTF-8 日志文件，再用工具读日志

教训：当环境有确定的崩溃模式时，绕开比修复更划算。

坑 3：PowerShell 吃掉了我的引号

提交前有个自查脚本需要传 JSON 参数。命令行里明明写对了，运行结果却报「参数不是合法 JSON」。

原因：PowerShell 在把参数传给子进程时会重新解析引号，嵌套引号全被吃掉。

解决办法：不用命令行传 JSON，改成 Python 端起进程、按精确 argv 传参。

教训：跨 shell 传结构化数据，永远别信引号。

五、一个我差点漏掉的事：链接验证

课程里有 100 个外部链接。翻译完看着没问题，但我做了一轮真实请求验证：

结果数量
自动通过48
需要人工判断44（LinkedIn 429/451、35 个不可达）
确认为失效8（7 个 GitHub 404 + 1 个 Figma 404）

如果没做这一步，交付物里会有 8 个死链接，而我自己完全不知道。

自动化能覆盖一半，剩下的一半必须人工判断——因为「429 限流」不等于「链接坏了」，「451 因法律原因不可用」也不等于「你写错了」。

六、结果

  • 中文覆盖率、术语一致率、格式完整性都逐项核对过
  • 交付物公开在 GitHub：github.com/Leo-web-lhy/c1-stanford-vibe-coding
  • AI 初评 91 分（满分 100）

但我觉得真正有价值的不是 91 分，是这套流程可复用：

换任何一份英文长文档，把术语表换掉、把分段规则调一下，同一套四阶段流水线直接能跑。

七、你可以直接拿走的三个动作

  1. 别让 AI 一次性翻全文。先抽术语表，人工确认，冻结，再分段翻。
  2. 每一个数字都带单位。字符数、字节数、行数，混着说就会错。
  3. 报「完成」之前，先做一次可复现的校验。链接真请求一遍，字符真数一遍，别靠「看起来对」。

最后问你一个问题：

你有没有过这种经历——AI 告诉你「已完成」，你信了，交上去才发现一半是空的？你当时是怎么发现的？
