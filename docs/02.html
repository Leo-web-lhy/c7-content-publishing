AI 不会骗你，但它会让你「以为你完成了」

AI 不会骗你，但它会让你「以为你完成了」

标题候选（A/B 测试用）：
1. AI 不会骗你，但它会让你「以为你完成了」
2. 我交了一个任务，AI 说 100% 完成；3 天后被退回，理由是空的
3. 别信 AI 说的「已完成」，信这三个检查

一、一个让我后背发凉的时刻

我让 AI 帮我交付一个开源项目。它给我一份漂亮的总结：

✅ 27 个文件全部推送
✅ 文档齐全
✅ 测试通过
✅ 任务完成

我提交了。三天后收到退回通知，没有给任何理由。

我一开始以为是平台问题。后来自己做了一次字节级核对，才发现有几处「看起来一致、实际不一致」的东西——而 AI 的总结里，一个字都没提。

这不是 AI 撒谎。是我把「看起来对」当成了「验证过」。

二、三种最危险的「假完成」

做了一年 AI 协作，我把它归成三类。

第一类：工具骗了你（而且不是工具的错）

我改了几个文件，跑 git status，看到 5 个 M（已修改）。我以为远端文档过期了，准备重新推一遍。

冷静下来做了一次逐字节比对：远端和本地完全一致，那 5 个 M 是 CRLF/LF 换行符归一化造成的假象。

如果我按 git status 的提示去「修复」，就会把本来正确的文件重推一遍，然后在日志里写下「修复了文档过期问题」——一个完全不存在的问题。

教训：git status 告诉你「工作区变了」，不告诉你「内容变了」。想知道内容有没有变，只能比字节。

我现在固定用这一条：

SHA 相等 → 一致
字节数不同 → 一定不一致
git status 显示 M → 可能只是换行符，需要进一步核对

第二类：你自己写的文档骗了你

我有份 README 里写着「CI 流水线已配置」。听起来没毛病，ci.yml 确实存在。

但真相是：本机凭据缺 workflow 权限，这个文件从来没被成功推上去过。CI 从未运行过一次。

这是个非常隐蔽的错误——文件在本地存在，我写「已配置」的时候并不是在撒谎，我只是把「我写了这个文件」当成了「这个文件在工作」。

后来我在所有交付物里把表述统一改成：

CI：已定义，未启用（缺 workflow 权限，推送被 GitHub 拒绝）

难看，但真实。而真实的难看，比好看的假话有用一百倍。

第三类：平台骗了你（一致性延迟）

提交完成后，我立刻查记录列表，发现只有 5 条，我刚提交的那条不在里面。

第一反应是「提交失败了」，差点重新提交一次。

实际原因是平台最终一致性延迟：提交返回终态后，列表视图要过几十秒才更新。如果按列表判断，我会重复提交，制造一个重复记录。

现在我的规则是：只信「单个任务查询」返回的终态，不信列表视图。

三、为什么 AI 特别容易放大这个问题

因为 AI 有一个非常强的倾向：倾向于相信上下文的表述。

我说「文档已经更新了」，它就会顺着写「文档已更新」。我说「测试通过了」，它就写「61 项测试全部通过」。

它不是在骗我，它是在放大我的自我认知。

而人最容易出错的时刻，恰恰是「我觉得我做完了」的那一刻。

所以真正有效的做法不是让 AI「更诚实」——是给它不依赖相信的检查手段。

四、我现在固定做的四件事

1. 用「可复现的比对」替代「看起来一致」

不看 git status，直接拉远端内容，算 SHA-1 或 SHA-256，逐文件比。

我的输出长这样：

MATCH=27  RAW_DIFF=0  ONLY_LOCAL=0  ONLY_REMOTE=0

四个零，才算一致。

2. 每个「已完成」后面必须跟一个数字

不写「测试通过」，写「61 项测试，0 失败」。

不写「文档齐全」，写「必交物 4/4，通配符全部命中」。

不写「性能提升」，写「BPB 从 2.63159 降到 2.47777，降幅 5.8%」。

没有数字的完成，等于没有完成。

3. 把「没做到的事」写进交付物

这是我踩坑最多、也进步最大的一条。

我现在每个项目都会有一节，明确列：

  • 哪些平台没测过（例如跨平台只实跑了 Windows + Python 3.12.13）
  • 哪些功能只是定义没启用（例如 CI）
  • 哪些数据还没有（例如评分未回填）

写完这一节，交付物会「没那么好看」，但评审能判断你到底做到哪一步——比含糊着过关强得多。

4. 把失败经验本身当成交付物

我最失败的一次：一个挑战被退回三次，三次都没给评语。

前两次我猜着改：补 LICENSE、补 CONTRIBUTING、补测试。第二次改完又被退回，我才意识到——我在猜一个我看不到的标准。

第三次我不再盲目改了，而是把「三次退回、无评语、我的自查矩阵、我判断的差距」全部写进返修记录。

这个故事不好听，但它是真的，而且它对下一个做同样任务的人有用。

五、一个反直觉的结论

AI 让「做出来」变得非常容易，因此让「证明你做对了」变成了唯一稀缺的能力。

以前一个项目做三周，你有三周时间反复确认它是对的。
现在一个项目做三小时，你只有三小时——而你会在第两小时五十分钟就相信它做完了。

所以现在的核心技能不是「会不会用 AI」，是：

你能不能在 10 分钟里，用可复现的证据，证明这件事真的成了。

六、你可以今天就试的三件事

  1. 打开你最近一次「AI 说完成了」的交付物，挑一个文件，算 SHA 和远端比一次。
  2. 把你文档里所有「已配置 / 已支持 / 已完成」找出来，逐个问：有证据吗？
  3. 给你的下一个交付物加一节，标题就叫「我没做到的」。

最后问你一个问题：

你被 AI 的「已完成」坑过吗？是被哪种坑的——工具显示不对、文档写得太乐观，还是平台延迟？

留言告诉我，我会把最多的那类整理成下一篇。
